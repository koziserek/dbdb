HTML output: a template filled with rows

A report, a list, a letter for each customer, as HTML.

The HTML output step writes a page instead of a table: a report, a list, a letter for each customer. You write the page as a template, and the step fills it with the rows it is given.

{"type": "html", "path": "Outputs/orders.html",
 "template": "<h1>{{ rows | length }} orders</h1>\n{% for r in rows %}<p>{{ r.id }}: {{ r.customer }}</p>\n{% endfor %}"}

The template is text in the step, so it is part of the project file. In the app it is the Template box of the step's settings, which says what is wrong with it as you type.

The language

Templates are written in the language of MiniJinja, which is the language of Jinja:

Written as Does
{{ r.customer }} puts a value into the page
{{ r["Unit Price"] }} the same, for a column whose name is not one word
{% for r in rows %} ... {% endfor %} repeats what is between for each row
{% if r.note %} ... {% else %} ... {% endif %} chooses
{{ r.name | upper }} passes a value through a filter
{# ... #} a comment, left out of the page

A template is given four things:

Name Is
rows the rows of the file, in the order they came
row the first of them, for a file that is about one thing
columns the names of the columns, to write a table of any input
params the run's parameters: {{ params.title }}

A column is always asked of a row: row.customer, or r.customer inside {% for r in rows %}. {{ customer }} by itself is an error.

A table of whatever columns arrive:

<table>
<tr>{% for c in columns %}<th>{{ c }}</th>{% endfor %}</tr>
{% for r in rows %}<tr>{% for c in columns %}<td>{{ r[c] }}</td>{% endfor %}</tr>
{% endfor %}</table>

Values are text

As everywhere in dbdb, a value is text and an empty value is the same as a missing one. In a template an empty value prints nothing, and {% if r.note %} is false for it.

A number is text too. {{ r.qty | int }} and {{ r.price | float }} make numbers of them, and a comparison needs that: {% if r.qty | int > 10 %}. Work sums and other figures out in the steps before (Map columns, Aggregate), which count in exact decimals, and let the template only place them. Filters such as | float and | sum count in floating point.

Headings for groups

groupby puts the rows with one value together, the groups in the order of their values:

{% for g in rows | groupby("customer") %}
<h2>{{ g.grouper }}</h2>
<ul>{% for r in g.list %}<li>{{ r.id }}</li>{% endfor %}</ul>
{% endfor %}

One file, or a file for each row or group

Without name the step writes the one file path, from every row. With name, path is a folder and name is a small template for the file name of each row. The rows that get one name make one file:

{"type": "html", "path": "Outputs/invoices",
 "name": "{{ row.customer }}/invoice-{{ row.id }}.html",
 "template": "<h1>Invoice {{ row.id }}</h1>"}
  • A name from a key is a file for each row; a name from a customer is a file for each customer, with that customer's rows as rows.
  • In the file name, row is the row the name is for.
  • The name has to be a place below the folder: a.html or 2026/a.html. A name that is empty, has .. in it or starts at the root stops the run, and nothing is written.
  • With no rows, the one file is still written (rows is empty and there is no row: test with {% if rows %}), and no file for each.

What is written into the page is escaped

A value goes into the page with &, <, >, the quotes and / escaped, so data cannot become markup or a script. {{ r.note | safe }} writes a value as it is: use it only for a column that holds HTML you trust. Inside a <script> write {{ r.name | tojson }}, and in the query of a link {{ r.name | urlencode }}.

The file name is not HTML and is not escaped.

The page is written as UTF-8: put <meta charset="utf-8"> in its head.

What a template cannot do

A template reaches only what it is given. It cannot take in another template or a file: {% include %}, {% import %} and {% extends %} are not part of the language here. It reads no database and no address. {% macro %} works, for a piece used several times in one template.

${name} in a template is left as it is, since JavaScript writes its own values that way. A parameter is {{ params.name }}. The path of the step takes ${name} as every path does.

Errors

What can be seen without rows is said before a row is read, and by dbdb-cli lint: a mistake in the grammar with its line, a name the template is not given, and a column asked of row that the input does not have.

step 2 (HTML output): its template uses `row.custmer`, and its input has no such column (it has `customer`, `id`)

A column asked of a row inside a loop (r.custmer) shows when the page is written. The run stops there, with the line, instead of leaving a gap. {{ r.x | default("") }} asks for a gap on purpose.

The run

  • The step holds its rows until its input has ended, since a page is written from all of them. They count against the run's memory limit.
  • Each file is written beside its place as <name>.part, and all take their names when every one is written. A run that fails leaves what was there.
  • A dry run fills every template and writes nothing.
  • The preview shows each file's name and its text.
  • In a browser the files go into the opened folder, or come as downloads.
  • A project with the step is written as "format": 7, so that an older dbdb says a newer one is needed.
