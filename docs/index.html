Documentation

How each part of dbdb works.

dbdb's pages on one subject each. The intro article says what dbdb is and how to get it.

Working with data

  • Expressions: The language of Map columns and Filter conditions.
  • Parameters and environments: ${name} in paths, connections and table names, and environments for test and production.
  • Comparing two sources: A target against its source after a load: which rows differ, and which only one side has.
  • Database output: Writing rows to PostgreSQL, SQL Server and SQLite tables.
  • HTML output: a template filled with rows: A report, a list, a letter for each customer, as HTML.
  • REST API and OData sources: Sources that read a REST API or an OData service.
  • Run history: The record every run leaves, and what it shows.
  • Notes: Pages of Markdown that travel with the project.

Running jobs

  • Job schedule: Running a job by itself, at set times, on one machine.
  • Runs on another machine: Asking another machine to run a job, and being the machine that runs it.
  • Pushing a file to another machine: A job that sends its result to another machine.

Sharing and safety

  • One project open in several places: Two windows, two computers, the app and the command line, on one project.
  • What sharing a project allows: What sharing a project hands over, and what a machine agrees to.
  • The vault: Where passwords live, and how they travel sealed.
  • Connectors: Models, servers and services a project reaches, set up once and named.

Assistants

  • The assistant: The Assistant pane: a conversation that can look at the project and build in it.
  • Asking an AI assistant for a project: What to ask an AI assistant that has dbdb-cli, to build a whole project.
  • Building a dbdb project: a guide for AI assistants: The guide an assistant reads: steps, the project file and every command. dbdb-cli guide prints it.
