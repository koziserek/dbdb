Expressions

The language of Map columns and Filter conditions.

A Map step can work a column out with an expression, and a Filter step can keep rows by a condition. Both are written in the same small language, which reads like the expression part of SQL:

upper(trim(last_name)) || ', ' || first_name
if(qty is null, 0, to_int(qty)) * to_number(price)
format_date(installed, 'dd.MM.yyyy', 'yyyy-MM-dd')
case when status in ('C', 'X') then 'CLOSED' else 'OPEN' end

Values

Written as Means
name the column name of the step's input
"Unit Price" a column whose name has spaces or other signs
'text' text; write '' for a quote inside
12, 1.5 numbers
${name} a parameter of the run
null, true, false no value, yes, no

Every value of a table is text, and an empty value is the same thing as a missing one: x is null and x = '' say the same.

From the ones that bind loosest to the ones that bind tightest:

A code with leading zeros such as 007 is text. < and the like are false when a side is empty. = holds between two empty sides and <> between an empty side and a value: there is no "unknown" as in SQL, so x <> 'A' keeps the rows where x is empty.

case when condition then value [when ...] [else value] end picks the first value whose condition holds.

Functions

Function Gives
if(condition, then, else) one of two values
coalesce(a, b, ...) the first value that is not empty
concat(a, b, ...) the values joined into one text
substr(text, start, length) part of a text; start counts from 1, length may be left out
left(text, n), right(text, n) the first or last n characters
trim(text), ltrim(text), rtrim(text) without spaces at the ends
upper(text), lower(text), title(text) in another case
lpad(text, length, pad), rpad(...) filled up to a length, with spaces unless pad is given; a longer text is kept whole
length(text) the number of characters
replace(text, from, to) every from replaced by to
contains(text, part), starts_with, ends_with yes or no
matches(text, 'regex') whether the text matches a regular expression
to_int(value) a whole number (' 12 ' and 12.00 are, 12.5 is not)
to_number(value) a number
to_decimal(value, scale) a number rounded to and written with scale decimals
round(value, scale) rounded half away from zero, to scale decimals or to a whole number
abs(value) without its sign
to_date(text, 'pattern') a date read by a pattern, given as yyyy-MM-dd (with HH:mm:ss when the pattern has a time)
format_date(text, 'from', 'to') a date read by one pattern and written by another
format_date(date, 'to') a yyyy-MM-dd date, such as today() or now() gives, written by a pattern: format_date(today(), 'yyyyMMdd')
add_days(date, n) a yyyy-MM-dd date n days later
today(), now() the day, or the moment, of the run
is_int(value), is_number(value), is_date(text, 'pattern') whether the conversion would work

Date patterns use the letters Talend and Java use: yyyy yy MM M MMM dd d HH mm ss SSS, and 'T' for fixed text.

When a value cannot be converted

to_int('abc') does not quietly give an empty value: the step stops and names the column and row, as in

step 4, column `qty`, row 12: to_int: `abc` is not a whole number

Where the data may be bad, test first: if(is_int(qty), to_int(qty), 0), or send the bad rows elsewhere with a Filter whose condition is is_int(qty).

The type of a new column

A Map column made by an expression gets its type from the expression: to_int gives a whole number, to_decimal and arithmetic a decimal, to_date a date, a comparison a boolean and everything else text. Outputs that have types (JSON, Excel, SQLite) write the values accordingly. A column that is nothing but another column's name keeps that column's type, width and pattern.

{"type": "map", "columns": [
  {"name": "label", "value": {"type": "expr", "expr": "upper(trim(name))"}}
]}
{"type": "filter", "filters": [], "condition": "to_int(qty) > 0"}
